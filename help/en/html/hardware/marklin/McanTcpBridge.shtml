Hardware Support: MCAN Protocol Serial-to-TCP Bridge

The MCAN TCP Bridge is a standalone CLI program that bridges Märklin CAN (MCAN) serial adapters to TCP/IP, allowing JMRI's CS2 Ethernet adapter to connect to physical serial MCAN devices over the network. This enables forwarding a single CC-Schnitte USB adapter to a remote computer or connecting multiple programs simultaneously.

Quick Start

  1. Building the shared library version is included in JMRI's build pipeline:
  2. Build the standalone version: 
    ant mcan-tcp-bridge-jar
    Output: dist/mcan-tcp-bridge.jar
  3. List available ports: 
    java -jar dist/mcan-tcp-bridge.jar --list
  4. Start bridge: 
    # Single device, default port 15731 on all network interfaces
java -jar dist/mcan-tcp-bridge.jar --port COM3         # Windows
java -jar dist/mcan-tcp-bridge.jar --port /dev/ttyUSB0 # Linux
  5. Configure JMRI: Add CS2 Ethernet connection to localhost:15731

Port Specification Format

The --port parameter accepts flexible specifications:

<serial>[:<bind_addr>][:<tcp_port>][,<serial>[:<bind_addr>][:<tcp_port>],...]
Example Result
--port COM3 COM3 → TCP 15731 (all interfaces)
--port COM3:50000 COM3 → TCP 50000 (all interfaces)
--port COM3:127.0.0.1:15731 COM3 → localhost:15731 only
--port COM2,COM3 COM2 → 15731, COM3 → 15732
--port COM2,COM3,COM4 COM2 → 15731, COM3 → 15732, COM4 → 15733
--port COM2:50000,COM3:50001 COM2 → 50000, COM3 → 50001

Overview

The bridge program creates one or multiple TCP servers that connect to one MCAN serial adapter each (such as the CC-Schnitte by CanDigitalBahn). One or multiple clients can connect to each TCP server simultaneously.

Key features include:

  • Bidirectional serial ↔ TCP bridge with message broadcasting
  • Multiple TCP client support (i.e. JMRI and product support software)
  • Multiple device support (bridge several adapters simultaneously)
  • Hot-plug support with automatic reconnection when devices are unplugged/replugged
  • Cross-platform support (Windows, Linux, macOS)
  • Command monitor for debugging and logging MCAN messages in a human readable format

Requirements

  • Java 11 or higher - same as JMRI
  • MCAN serial adapter (e.g., CC-Schnitte USB adapter)
  • JMRI installation or standalone bridge JAR

Building the Bridge

The bridge is built as part of JMRI by default. For standalone deployment, use ant targets:

Build Standalone JAR

Using Ant:

cd /path/to/JMRI
ant mcan-tcp-bridge-jar

Using Maven:

cd /path/to/JMRI
mvn antrun:run -Danttarget=mcan-tcp-bridge-jar

This creates dist/mcan-tcp-bridge.jar - a self-contained JAR with all dependencies embedded (~5MB).

Run from Development Environment

ant mcan-tcp-bridge

This runs the bridge using JMRI's full classpath (useful for development and debugging).

Using the Bridge

List Available Serial Ports

java -jar mcan-tcp-bridge.jar --list

Output example:

Available serial ports:

  COM3
    Description: USB Serial Port
    Location: USB

Start the Bridge

Windows:

java -jar mcan-tcp-bridge.jar --port COM3

Linux:

java -jar mcan-tcp-bridge.jar --port /dev/ttyUSB0

macOS:

java -jar mcan-tcp-bridge.jar --port /dev/cu.usbserial-AB0JUFVA

Multiple Devices

The bridge can manage multiple serial adapters simultaneously, each on its own TCP port:

java -jar mcan-tcp-bridge.jar --port COM3,COM4,COM5

This creates three TCP servers:

  • COM3 → TCP port 15731
  • COM4 → TCP port 15732
  • COM5 → TCP port 15733

You can also specify custom ports:

java -jar mcan-tcp-bridge.jar --port COM3:50000,COM4:50001

Command Line Options

Usage: java -jar mcan-tcp-bridge.jar --port <serial_port> [options]

Options:
  --port, -p <port>    Serial port name (required)
                       Windows: COM1, COM3, etc.
                       Linux:   /dev/ttyUSB0, /dev/ttyACM0, etc.
                       macOS:   /dev/cu.usbserial-*

  --tcp, -t <port>     TCP server port (default: 15731)
  --baud, -b <rate>    Serial baud rate (default: 500000)
  --monitor, -m        Enable monitor mode with decoded messages
  --list, -l           List available serial ports and exit
  --help, -h           Show this help message

Examples:
  java -jar mcan-tcp-bridge.jar --port COM3
  java -jar mcan-tcp-bridge.jar --port /dev/ttyUSB0 --tcp 12345
  java -jar mcan-tcp-bridge.jar --port COM3 --monitor

Connecting JMRI to the Bridge

Configure JMRI to connect to the bridge as if it were a CS2:

  1. Start the bridge program
  2. Open JMRI and go to Edit → Preferences
  3. Click the Connections tab
  4. Click + to add a new connection
  5. Select:
    • System manufacturer: Märklin
    • System connection: Command Station 2 (CS2)
    • Connection: Network Connection (TCP)
    • IP Address/Host Name: localhost (or IP of bridge computer)
    • Port: 15731 (or custom port if specified)
  6. Click Save and restart JMRI

Hot-Plug Support

The bridge supports USB hot-plugging without requiring a restart:

  • Starting without devices: Bridge can start even if the MCAN adapter is not plugged in or powered off
  • Unplugging during operation: Bridge continues running, TCP clients stay connected
  • Automatic reconnection: Bridge detects when device is replugged and reconnects within 5 seconds
  • Graceful degradation: TCP messages are accepted but discarded until device reconnects

This makes the bridge suitable for 24/7 operation as a system service.

Monitor Mode

Enable monitor mode to see decoded MCAN messages in real-time:

java -jar mcan-tcp-bridge.jar --port COM3 --monitor

Monitor mode displays:

  • Raw CAN frames in hex format
  • Decoded message components (priority, command, hash, DLC, address, data)
  • Human-readable command descriptions
  • Device identification (CS2, MS2, Gleisbox, etc.) from protocol messages
  • ASCII representation of data bytes

Running as a Service

Linux systemd Service

Create /etc/systemd/system/mcan-tcp-bridge.service:

[Unit]
Description=MCAN Protocol Serial-to-TCP Bridge
After=network.target

[Service]
Type=simple
User=jmri
WorkingDirectory=/opt/mcan-tcp-bridge
ExecStart=/usr/bin/java -jar /opt/mcan-tcp-bridge/mcan-tcp-bridge.jar --port /dev/ttyUSB0
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target

Enable and start:

sudo systemctl daemon-reload
sudo systemctl enable mcan-tcp-bridge
sudo systemctl start mcan-tcp-bridge
sudo systemctl status mcan-tcp-bridge

Windows Service

Create a Windows service using PowerShell and native service infrastructure.

Step 1: Create a wrapper script C:\mcan-tcp-bridge\run-bridge.bat:

@echo off
cd /d C:\mcan-tcp-bridge
"C:\Program Files\Java\jdk-11\bin\java.exe" -jar mcan-tcp-bridge.jar --port COM3

Step 2: Create the service using PowerShell (run as Administrator):

# Create the service
sc.exe create McanTcpBridge `
  binPath= "C:\mcan-tcp-bridge\run-bridge.bat" `
  DisplayName= "MCAN TCP Bridge Service" `
  start= auto

# Configure service description
sc.exe description McanTcpBridge "Bridges MCAN serial adapters to TCP/IP for JMRI"

# Start the service
sc.exe start McanTcpBridge

# Check service status
sc.exe query McanTcpBridge

Alternative: Use PowerShell script for service management:

# Create service with New-Service cmdlet
New-Service -Name "McanTcpBridge" `
  -BinaryPathName "C:\mcan-tcp-bridge\run-bridge.bat" `
  -DisplayName "MCAN TCP Bridge Service" `
  -Description "Bridges MCAN serial adapters to TCP/IP for JMRI" `
  -StartupType Automatic

# Start the service
Start-Service -Name "McanTcpBridge"

# Check service status
Get-Service -Name "McanTcpBridge"

Service Management:

# Stop service
sc.exe stop McanTcpBridge
# or: Stop-Service -Name "McanTcpBridge"

# Remove service
sc.exe delete McanTcpBridge
# or: Remove-Service -Name "McanTcpBridge"

# View service logs (Event Viewer)
Get-EventLog -LogName Application -Source "Service Control Manager" -Newest 20

Note: For production use, consider using a proper service wrapper like WinSW which provides better logging and error handling than batch file wrappers.

Troubleshooting

Serial Port Not Found

Error: Failed to open serial port: COM3

Solutions:

  1. Check that the CC-Schnitte is plugged in
  2. Verify the port name with --list
  3. On Linux, check permissions: sudo usermod -a -G dialout $USER (then logout/login)
  4. Ensure no other program is using the port

TCP Port Already in Use

Error: java.net.BindException: Address already in use

Solutions:

  1. Use a different port: --tcp 12346
  2. Check what's using port 15731: netstat -an | grep 15731
  3. Stop the conflicting process

JMRI Won't Connect

Check:

  1. Bridge is running and showing "TCP server listening on port 15731"
  2. Firewall isn't blocking port 15731
  3. Correct IP address in JMRI (use localhost if on same machine)
  4. JMRI connection type is "CS2 Ethernet" with TCP protocol

No Data Being Received

Enable debug logging:

java -Dorg.slf4j.simpleLogger.defaultLogLevel=DEBUG -jar mcan-tcp-bridge.jar --port COM3

Also check:

  • CC-Schnitte is powered and connected to track
  • Serial port LED indicators are active
  • Test with Märklin software first to verify hardware works

Performance

  • Throughput: Supports full 500kbaud serial bandwidth
  • Clients: No hard limit, tested with 10+ concurrent clients
  • Memory: ~50MB RAM footprint

Connect virtual serial ports to the bridge

JMRI provides helper scripts for creating virtual serial ports which connect to the bridge. The bridge contains code which avoids garbled messages when multiple clients attempt to send to the bus at the same time. This allows to run both JMRI and product support software such as CanDigitalBahn's WeichenChef Configuration utility simultaneously and even through a wifi connection. Traditionally the configuration tool needs to run locally on the computer connecting to the CC-Schnitte adapter. It would own the adapter exclusively and JMRI would need its own physical adapter. Because of hotplugging support, the bridge may run on a small dedicated computer such as a Raspberry Pi, and both JMRI and the configuration tool can connect to it remotely. Put your laptop or dispatcher desk at comfortable distance from your layout.

Linux and macOS

Use scripts/create-mcan-virtual-port.sh (requires socat):

./scripts/create-mcan-virtual-port.sh /dev/ttyVCOM0 localhost 15731

This creates a virtual serial port /dev/ttyVCOM0 that connects to the bridge's TCP server. Configure your programmer software to use this virtual port.

Windows

Use scripts/create-mcan-virtual-port.ps1 (requires com2tcp):

.\scripts\create-mcan-virtual-port.ps1 -VirtualPort COM99 -TcpHost localhost -TcpPort 15731

Or for com0com-based virtual ports, use scripts/create-mcan-virtual-port-com0com.ps1.

These scripts enable serial software to share the CC-Schnitte adapter with JMRI via the bridge's message multiplexing. The bridge broadcasts serial data to all TCP clients (both JMRI and virtual port connections), and any client can send commands to the serial port. The bridge takes care of buffering and avoiding write conflicts

Notes

  • The bridge is completely transparent to JMRI - it doesn't interpret or modify MCAN messages. All protocol handling is done by JMRI and the CC-Schnitte adapter.
  • Multiple JMRI instances can connect simultaneously. All clients receive broadcast serial data, and any client can send commands to the serial port.
  • The bridge uses automatic baud rate detection but defaults to 500,000 baud for CC-Schnitte adapters. Serial parameters are: 8 data bits, 1 stop bit, no parity, no flow control, RTS/DTR enabled.
  • If the serial device is unplugged during operation, the bridge continues running and TCP clients stay connected. When the device is replugged, the bridge automatically reconnects within 5 seconds.
  • The bridge can run as a system service (Linux systemd or Windows NSSM) for 24/7 operation.
